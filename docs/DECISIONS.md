| D-045 ✅ | **Services (Webmaster → Services): a query-builder mode AND a raw-SQL mode, on one flat permission set** (`services.read`/`write`/`sql` — not per-item like content types, since a Service has no per-item authorship or publish workflow). SQL mode is real but the safety layers are **asymmetric across engines, by design, and stated as such rather than oversold**: the single-statement + must-start-with-SELECT/WITH check is the actual backstop on PostgreSQL (its simple-query protocol allows `;`-stacked statements when a query has zero parameters — confirmed live, a stacked `DROP TABLE` succeeded before this check existed), where SQLite/MySQL already refuse multi-statement text at the driver level; the keyword blocklist is the primary defense against a write (a rolled-back transaction is not reliable — MySQL DDL auto-commits inside one); a per-dialect statement timeout is real cancellation on PostgreSQL (`SET LOCAL statement_timeout`, value inlined because Postgres's `SET` rejects a bound parameter), real on MySQL for genuine row-scanning work via `SET SESSION MAX_EXECUTION_TIME` (confirmed **not** to interrupt `SLEEP()` specifically — only a real query scan), and not possible at all on SQLite (`better-sqlite3` is synchronous, dev/test only per D-018). | D-051 ✅ | **Scheduler (Automation → Scheduler), Phase 2 of the Events/Webhooks/Scheduler plan**: admin-editable recurring automation — run an existing Service, or fire a Webhook, on an interval (≥ 1 minute) or a cron expression.
