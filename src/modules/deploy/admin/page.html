Deploy

Push this installation's code, and what it keeps only in its database, to the repository your production servers run from. Servers pull it with Updates, which brings the changes in and adds the data without overwriting what they have.

Deployment repository
This server needs push access (an SSH key or a stored git credential); a password in the URL is refused. The branch is created on the first deploy if it doesn't exist.
·
What to deploy

Always included: everything in the application folder except node_modules, data (media, libraries, the local database), .env and logs. Those stay on each server and are never deployed or overwritten.

No installed or cloned themes, and no uploaded plugins, are stored only in the database.

Data to copy

Choose, table by table, what a deploy carries to production. Table structure is always copied. Add missing adds records production lacks. Sync also updates a record dev changed, but only if nobody changed it on production too; otherwise it waits for you under "Waiting for you". Nothing is ever deleted, and records are matched by name, slug or email, never by id. Secrets (passwords, API keys, webhook secrets) never travel.

Settings to copy
Every setting is copied by default; untick the ones that should stay different on production (the site address, mail, maintenance mode…). A setting someone changed on production is never overwritten without your say-so. Keys and passwords are never copied.
Never copied: keys and secrets
These are encrypted for each server. Enter them on production under Settings.
